## Storage — GCS buckets, from A1 onward

The repo holds **code and source tables only**.

- Run `gcloud storage ls`, then **confirm with Asif which bucket is for documents
  before the first write**.
- Documents: `gs://{bucket}/specs/{STATE}/{project_id}/{doc_type}_{filename}.pdf`,
  one object per document, with object metadata `source_url`, `fetch_date`,
  `doc_type`, `portal`. **Never commit a PDF to git.**
- Structured output (pull logs, classifier extractions — divisions,
  basis-of-design brands, page cites) goes to Cloud SQL Postgres, keyed so every
  fact carries its GCS object path + source URL. If tables don't exist,
  **propose a schema to Asif before creating it**.
- `pull_log.csv` in the repo stays a small run-summary artifact, not the
  document store.
- Add `*.pdf` and `specs/` to `.gitignore`; verify with `git check-ignore`.

## Step 3 — Run at scale; nothing runs on Asif's laptop

The laptop is for development only. Production runs in the cloud on the existing
stack.

- Package each adapter into the pipeline container, deploy as **Cloud Run Jobs**
  in the same GCP project as the buckets and Postgres. Trigger with **Cloud
  Scheduler**: daily for A1/A2/A4 + Tier 1 delta check; weekly for the full A3
  spec-book crawl.
- **GitHub Actions for CI/CD** (test + deploy jobs on merge) and optionally the
  lightest crons. Heavy crawling belongs in Cloud Run Jobs, where runtime,
  memory and retries are managed.
- Secrets (SAM.gov key, DB credentials) in **GCP Secret Manager**, injected into
  jobs. Never in the repo, never on the laptop.
- The classifier at scale is a **Claude API call inside the pipeline** (batch the
  week's new PDFs, extract divisions/brands/citations into Postgres), not an
  interactive session. Keep interactive sessions for development, debugging and
  naturally occasional judgment work — dead-link repair, county scouting,
  quarterly re-verification.
- Every job writes a **run summary row** (start, end, source counts, funnel
  numbers, errors) to Postgres, so the weekly report is generated by query rather
  than from memory.

## Standing rules — never override

Public data only; every fact cited to its public source with fetch date. **No
accounts created by automation, no payments, no submissions on any portal, no
Dodge/ConstructConnect/plan-room content ever.** Log blockers — `registration
required`, `unreadable format`, `dead link` — instead of working around them.
When a portal URL 404s, find the migrated URL, update the source CSV, and note it
in the commit.

## Report back each session

What shipped · funnel numbers (projects → docs → confirmed spec docs → recovered
by search) · source-table corrections made · anything needing a human decision.
That loop is how the skill and plan stay true.
