What this document is
The requirements for what a licensed user sees after they sign in. It covers the three screens, the tracking model, and notes. It does not cover the public index pages, pricing and checkout, the ingestion pipeline, or the brand-visibility product. Numbers in the design file are illustrative except the Maine State Prison record, which is live data from specindex.ai.

1. The problem

Signing in changes almost nothing today. The user lands on the same marketing page with a filter block bolted to the top: a hero headline, a paragraph of positioning, 50 state chips, a search field, and six dropdowns before a single project appears. Then, once they track a project, tracking goes nowhere. There is no screen that lists what they track, no stage, no history, and no way to write down what they learned on a call. The most valuable thing a rep knows about a project is what somebody told them on the phone, and today the product has nowhere to put it.

The rule
The logged-out index sells. The logged-in app works. Nothing that exists to persuade a visitor belongs on a screen a licensed user opens every morning.
Notes are the moat
Public data can be matched by anyone with a crawler. What cannot be matched is a year of a rep's own account of who said what on which job, sitting on top of that data. Notes are the primary call to action in the signed-in app, and the reason the licence renews. Every screen should push toward writing one, and no screen should bury the composer.

3. Information architecture

Territory is set once in the sidebar and every screen inherits it. That single move removes the 50-state chip grid from the top of the projects list, which was the largest source of visual noise on the first screen.

SurfaceAnswers
TodayWhat changed since I last looked, and what is new and early enough to influence
PipelineWhat am I chasing, and where does each one stand
ProjectWhat do we hold on this job, what is missing, and what did I do about it
DiscoverEverything my licence covers, in one dense list I can filter, select, and track in bulk
ReportingCoverage on my territory, counted directly and never projected

4. Today

Today is the first screen after sign-in. It opens with what changed on tracked projects, because a change on something the user already chose is worth more than any new record. Below that sits a short scored list of new projects in territory. No hero, no positioning copy, no filter wall.

RequirementDetail
Change feedTyped entries (Spec, Doc, Team, New) on tracked projects only, most recent first, each opening the project record
Scored listAt most six projects, ranked by how much of the spec is still winnable, not by recency. Track is a one-click action on the row
Pipeline summaryCount per stage, each row jumping to the board
Data freshnessLast-run time per source class. A stale bar is a feature, not a bug to hide
Empty stateA user with nothing tracked sees the scored list first and a single line explaining what tracking does
If you ship one thing
Ship the change feed. It is the only screen in the product that gives a reason to open it tomorrow. Everything else can be reached by search.

4.1 Discover: everything the licence covers

Today is deliberately short. Discover is the answer to "show me everything I am entitled to", and it has to be a dense list rather than a card wall: one row per project, sortable, with the same select-and-track and save-a-view controls as Today.

RequirementDetail
Entitlement is the frameHeader states the count the licence covers ("412 commercial projects your licence covers"). No upsell, no locked rows
Row densityCheckbox, score, name and meta, stage, value, track. Roughly 44px per row, header row sticky in production
FiltersOne segmented control: All, Spec still open, Discovered with no spec, Bid opens soon. Deeper filtering lives behind search, not a dropdown wall
Same two actionsSave this view and select-and-track behave identically to Today. One mental model, two screens
PagingInfinite scroll with a visible "showing N of 412". Sort defaults to priority score

4.2 Saving a view and tracking in bulk

Two actions carry the whole workspace: saving a search so it re-runs itself, and tracking a project so changes come to you. Both have to cost one click. Neither gets a settings page.

RequirementDetail
Save this viewA button next to the filter row on any list. It saves the current territory and filter, nothing more to configure
Pre-filled nameThe name field opens with a generated name ("Maine · Spec still open"), so Enter alone finishes the job. Escape cancels
Where it landsTop of the sidebar Saved views list with a live result count, plus a confirmation line that names it
Sidebar plus buttonSame flow, started from the Saved views header
Select and trackA checkbox on every project row. Selecting any row raises a bar with the count, Clear, and "Track N projects", all landing at Watching
Single trackThe row button stays. Clicking it again untracks, with no confirmation dialog
Phase 2Email digest per saved view, and "track everything in this view" as a standing rule

5. Pipeline

Tracking has to arrive somewhere. Pipeline is a four-stage board over everything the user tracks, reachable from the sidebar, the top bar count, and the Today summary.

StageMeans
WatchingTracked, no contact yet. Default on first track
Specifier engagedA person has been reached: architect, engineer, owner, or contractor
Spec namedYour brand appears in a document, as basis of design or approved equal
Closed outWon, lost, or dead. Kept for the record, not for the queue

Stage is set by the user and never by the pipeline. Automated data changes the project record; it does not move a card. Each card shows the score, the value, the note count, and one urgency line when a date is close.

6. Project record and notes

The project record keeps the existing structure (the read, facts, tabs, activity) and adds two things: a stage control in the right rail so tracking state is changeable where it is read, and a notes panel under the tabs.

RequirementDetail
Placement"Log what happened" sits directly under the header card, above the document tabs. It is the first thing below the fold, never the last
Note entryFree text, always visible, saved on click or Cmd plus Enter. No modal and no required fields
Entry points"Add note" on every pipeline card, and a Your notes card at the top of the Today rail showing the three most recent across projects
Auto-trackSaving the first note tracks the project at Watching. Writing something down is the intent
Note kindsNote, Call, Email, Meeting. Defaults to Note, changed after the fact, never blocking the write
SeparationNotes render in their own panel, visually distinct from the sourced activity feed. A user must never wonder whether a line came from the public record or from a colleague
PrivacyNotes belong to the territory licence, never to the public project page, and never to model training
Next actionPhase 2: an optional date on a note, surfaced on Today as a due item
This is the P0 risk
Reps already have a CRM they are told to use and do not. We win by being the place the data already lives, so the note costs four seconds and no context switch. The moment notes require a form, a stage, and a required field, we have built the thing they avoid.

7. Discovery states

SPX-6700284, the Maine State Prison Gatehouse Improvement Project, is the demo record because it is the earliest state we hold: discovered through search grounding before any bid portal listed it. Priority score reads two dashes, not a number. Manufacturers, documents, and divisions all read zero. Every tab says plainly what is missing and why.

That is the demonstration, not an apology for thin data. A discovered project with no spec is the whole argument: the index knew about the job before the documents existed, and tracking converts that head start into an alert the day the specification publishes.
